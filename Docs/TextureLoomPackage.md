# Texture Loom package contract

A `.textureloom` file is a ZIP archive with `manifest.json` at its root. Loom Factory exports it inside the selected source folder's `.loom-factory/exports` directory. It contains an imported Create ML classifier, trained native map models and the map models' safetensors weights; original images are never included.

The manifest uses `schema: texture-loom.package.v1` and identifies the system with `id`, `name`, and `version`. `classifier` describes its CoreML `path`, `architecture`, `inputName`, `outputName` and labels (`id`, `name`, `sourceLabel`). `sourceLabel` is the original string returned by the imported CoreML classifier; consumers map it onto the dataset's stable `id`. A Create ML classifier has no separate safetensors weights. The optional classifier `weightsPath` is retained for compatible earlier tensor classifiers. Each entry in `categories` identifies a dataset with `id`, `name`, `version` and `models`. Model entries contain `map` (`depth`, `roughness`, `normal`), `format: coreml`, `path`, `weightsPath`, `architecture`, and `sha256` of its trainable weights. `files` provides SHA-256 hashes of the native model files, weights and training descriptors. Paths are relative and cannot traverse outside the package.

Native map models accept a float32 RGB tensor named `rgb`, in NCHW layout and sRGB values from zero to one. Map outputs are named `material_map`: depth and roughness have one channel; normals have three OpenGL RGB channels. Map spatial dimensions are flexible from 32 to 8192. The classifier uses its declared fixed RGB image input or RGB NCHW tensor dimensions. Image-input classifier records include `inputWidth`, `inputHeight` and `inputColorSpace: RGB` for the input preview; native CoreML performs the model's internal preprocessing. Consumers use the manifest's actual input and string-output names rather than assuming `rgb` and `dataset`. Labels lacking `sourceLabel` return their dataset ID directly.

Factory prepares Create ML training data as a new directory with one category subfolder and one symbolic link to a native 1,024 × 1,024 diffuse image per material folder. It never resamples or copies the originals. Materials with conflicting category tags, missing tags or missing 1K diffuse images are reported as skipped. Existing review state does not prevent exporting tagged images; review and classifier training happen in the chosen workflow. Any safe folder-name mapping needed for Create ML remains in the source folder's `.loom-factory/classifier-data-exports` catalog. Import validates every classifier class against the current source categories before storing the model in that source project's runs.

Texture Studio's build validates the package and compiles its CoreML assets into the app. This bundled base is immutable after installation. The application provides no base-model replacement picker and no base-model trainer.

A `.loomlora` adapter uses `schema: texture-loom.adapter.v1`, identifies its `baseModel` by `id` and `version`, and identifies matching datasets by their IDs and versions. Each map adapter provides LoRA safetensors weights, a fused CoreML override for native inference, and `baseSHA256` identifying the exact base weights. Disabling an adapter restores the bundled model without mutating it. Loom Workshop must refuse a mismatched base or dataset version.

CoreML conversion follows [Apple's PyTorch conversion workflow](https://apple.github.io/coremltools/docs-guides/source/convert-pytorch-workflow.html). Optional publication uses one Hugging Face model repository for the complete package, following the [Hub upload API](https://huggingface.co/docs/huggingface_hub/guides/upload).
